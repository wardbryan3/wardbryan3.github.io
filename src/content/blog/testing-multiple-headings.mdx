## Introduction

This is a test post designed to be long enough to require scrolling. It contains multiple headings at different levels so we can verify the table of contents, the scroll tracking, the prev/next navigation, and the overall layout.

The purpose of this post is purely functional testing. Each section below covers a different aspect of the site's behavior.

## Getting Started With Testing

Before we dive into the details, let's set up some expectations. This section covers the basics of what we're testing.

### Test Environment

The test environment consists of a mobile-responsive Astro site with a three-column blog layout. The layout includes:

- A left sidebar with blog navigation
- A center content area with the article text
- A right column with an auto-generated table of contents
- A terminal panel that can be expanded or collapsed

### Scope of Testing

We are verifying several features simultaneously:

- The table of contents should list all h2 and h3 headings
- Scrolling should highlight the active heading in the TOC
- The prev/next navigation should appear at the bottom
- The layout should be responsive at different breakpoints

## Detailed Analysis

Now let's go deeper into each component that needs verification. This section contains several subsections.

### Table of Contents Behavior

The TOC is built using a React component with IntersectionObserver. It watches all h2 and h3 elements in the article and highlights the one currently in view. This requires:

1. Correct heading IDs generated by Astro's MDX processor
2. The observer correctly ordering headings by DOM position
3. Proper cleanup of stale active states

### Terminal Persistence

The terminal uses sessionStorage to persist its open/closed state across page navigations. When you navigate from one blog post to another, the terminal should remember whether it was expanded or collapsed.

### Mobile Responsiveness

On viewports narrower than 768px, the layout collapses to a single column. The sidebar and TOC are hidden, and the terminal switches to a floating overlay mode. A toggle button in the nav bar opens and closes it.

## Code Examples

Here is a block of code to demonstrate syntax highlighting and scrolling:

```python
def fibonacci(n):
    """Generate the nth Fibonacci number."""
    if n <= 0:
        return 0
    elif n == 1:
        return 1
    else:
        a, b = 0, 1
        for _ in range(2, n + 1):
            a, b = b, a + b
        return b

def main():
    for i in range(20):
        print(f"fib({i}) = {fibonacci(i)}")

if __name__ == "__main__":
    main()
```

## Performance Considerations

This section discusses performance aspects of the layout.

### Render Performance

The page renders a React terminal component with `client:load`, which means it hydrates immediately. The TOC also uses a React component with `client:load`. These are the two interactive elements on the page.

### Network Performance

The page loads Google Fonts (Inter and JetBrains Mono) from an external CDN. The RSS feed link enables autodiscovery. The build output is a static site with prerendered HTML for each blog post.

## Edge Cases

Let's cover some edge cases that could break the layout.

### Very Long Headings That Might Wrap to Multiple Lines

This is a deliberately long heading that exists solely to test what happens when the table of contents entry wraps to multiple lines and whether the layout stays intact under such conditions without breaking or overflowing.

### No Headings

If a blog post has no h2 or h3 headings, the TOC column should simply not render. The layout should degrade gracefully to a two-column or single-column layout depending on the viewport.

### Single Heading

If a blog post has only one heading, the TOC should still render correctly with a single entry. The IntersectionObserver should track it properly.
